1. Resumen Ejecutivo

El Sistema de Créditos IPSFA es una aplicación web full-stack para la gestión de clientes, créditos, cuotas y conciliaciones bancarias de tres tiendas físicas: Caracas, Maracay y Maracaibo.

Backend
Node.js 20+ con Express.js. API REST con autenticación JWT. Conexión a PostgreSQL 18+ mediante pg pool.
Frontend
SPA (Single Page Application) en JavaScript vanilla. Sin frameworks. UI responsive con CSS puro. Gráficos con ApexCharts.
Base de Datos
PostgreSQL con tablas por tienda (tienda_caracas, tienda_maracay, tienda_maracaibo) + tablas de pagos normalizadas (pagos_caracas, etc.).

Roles de Usuario

RolPermisosRestricciones
administradorAcceso total. Crea/edita/elimina usuarios. Borra cuotas. Ve reportes de todas las tiendas.Ninguna
operadorCrea clientes, registra pagos, ve su tienda asignada.No puede borrar cuotas ni ver otras tiendas. No exporta PDFs sensibles.

5. Flujo de Datos — Cómo se Guardan las Cuotas

5.1 Creación de un Nuevo Crédito (POST)

  1. El usuario completa el formulario en 3 pestañas: Datos de Factura → Depósito Inicial → Plan de Cuotas.
  2. El frontend calcula en tiempo real:
    • monto_usd = monto_bs / tasa_bcv
    • inicial_usd = inicial_bs / tasa_inicial
    • deuda_usd = monto_usd - inicial_usd
    • monto_cuota_usd = deuda_usd / cuotas
  3. El frontend envía POST /api/tiendas/{tienda} con el payload JSON.
  4. El backend (crearCliente en routes/tiendas.js):
    • Filtra solo los campos permitidos (ALLOWED_FIELDS_INSERT).
    • v6.10-fix: Incluye explícitamente cuotas en el INSERT para evitar que PostgreSQL use el DEFAULT 11.
    • Ejecuta INSERT INTO tienda_XXX (...) VALUES (...).
    • Retorna el registro creado con RETURNING *.

5.2 Registro de una Cuota (PUT con pagos_extra)

  1. En Conciliaciones Bancarias, el usuario busca una factura por número.
  2. El backend devuelve el cliente con su array pagos_extra (JOIN con tabla de pagos).
  3. El usuario llena: monto (Bs), referencia, fecha, tasa BCV. El frontend calcula automáticamente monto_usd = monto_bs / tasa.
  4. Al guardar, el frontend envía PUT /api/tiendas/{tienda}/{id} con: 
    {
  "pagos_extra": [{
    "nro_cuota": 1,
    "monto_bs": 300000,
    "referencia": "1212",
    "fecha": "2026-08-15",
    "tasa_bcv": 772.5441,
    "monto_usd": 388.33
  }]
}
  5. El backend (actualizarCliente):
    • Recorre cada pago del array y ejecuta INSERT ... ON CONFLICT (factura_id, nro_cuota) DO UPDATE en la tabla pagos_XXX.
    • Luego recalcula totales haciendo SELECT SUM(monto_bs), SUM(monto_usd), COUNT(*) FROM pagos_XXX WHERE factura_id = $1.
    • Suma el inicial si existe.
    • Calcula deuda = monto_factura - totalDepositado.
    • Actualiza las columnas de resumen en la tabla principal: monto_depositados, deuda, total_depositado_usd, deuda_usd, cuotas_pagadas, proxima_cuota.

5.3 Eliminación de Cuotas (v6.9.1+)

  1. El administrador abre el modal de edición, marca checkboxes de cuotas a eliminar y presiona "Borrar Seleccionadas".
  2. El frontend envía PUT /api/tiendas/{tienda}/{id} con: 
    { "eliminar_cuotas": [2, 3] }
  3. El backend ejecuta: 
    DELETE FROM pagos_XXX WHERE factura_id = $1 AND nro_cuota = $2
    por cada cuota en el array.
  4. Luego recalcula totales (paso 5.2) y actualiza la tabla principal.
Flujo resumido: Las cuotas individuales viven en pagos_caracas/maracay/maracaibo. La tabla principal solo guarda los totales agregados para consultas rápidas. Cada PUT recalcula estos totales desde la tabla de pagos, garantizando consistencia.

Recálculo de Totales (v6.10)

Después de cualquier modificación de pagos, el backend ejecuta:

// 1. Leer todos los pagos de la tabla normalizada
const pagosResult = await pool.query(
  `SELECT monto_bs, monto_usd FROM ${tablaPagos} WHERE factura_id = $1`, [id]
);

// 2. Sumar totales
let totalDepositadoBs = 0, totalDepositadoUSD = 0, cuotasPagadas = 0;
for (const pago of pagosResult.rows) {
    if (parseFloat(pago.monto_bs) > 0) {
        totalDepositadoBs += parseFloat(pago.monto_bs);
        totalDepositadoUSD += parseFloat(pago.monto_usd);
        cuotasPagadas++;
    }
}

// 3. Sumar inicial (si es registro nuevo v6.7+)
if (esNuevo) {
    totalDepositadoBs += parseFloat(cliente.inicial_bs) || 0;
    totalDepositadoUSD += parseFloat(cliente.inicial_usd) || 0;
}

// 4. Calcular deudas
const deudaPendienteBs = montoFactura - totalDepositadoBs;
const deudaPendienteUSD = montoFacturadoDivisa - totalDepositadoUSD;

// 5. Guardar totales en tabla principal (legacy + nuevas columnas)
UPDATE tienda_XXX SET
    monto_depositados = $1,
    deuda = $2,
    total_depositado_usd = $3,
    deuda_usd = $4,
    cuotas_pagadas = $5,
    proxima_cuota = $6
WHERE id = $7

6.3 routes/auth.js — Autenticación

  • POST /api/auth/login: Valida email/password, genera JWT (expira en 24h), guarda sesión en tabla sesiones, retorna token + datos de usuario.
  • POST /api/auth/logout: Marca sesión como inactiva en BD y limpia localStorage.
  • POST /api/auth/refresh: Renueva token si la sesión sigue activa.
  • GET /api/auth/verificar-sesion: Valida token y retorna datos del usuario.

6.4 routes/bcv.js — Tasas de Cambio

  • GET /api/bcv/actual: Devuelve la tasa BCV más reciente de la tabla tasas_bcv.
  • GET /api/bcv/fecha/:fecha: Devuelve tasa histórica para una fecha específica (formato YYYY-MM-DD). Si no existe, usa la tasa actual como fallback.

6.5 routes/reportes.js

Genera reportes filtrados por fecha, estado, monto y nombre. Devuelve JSON con:

  • datos: Array de clientes que coinciden
  • resumen: Totales agregados (clientes, deuda, depositado, mora, promedio)
  • total: Cantidad de registros

8. Autenticación y Seguridad

8.1 JWT (JSON Web Tokens)

  • Payload: { id, email, rol, tienda, token_version, iat, exp }
  • Expiración: 24 horas
  • Almacenamiento: localStorage (token) + cookie HTTPOnly opcional
  • Revocación: Al cambiar password, rol, activo o IP asignada, el backend incrementa token_version en la BD. Los tokens antiguos con versiones menores son rechazados.

# 2. Instalar dependencias
npm install

# 3. Crear base de datos en PostgreSQL y restaurar schema
psql -U postgres -d creditos_ipsfa -f bd.sql

# 4. Crear usuario admin inicial (directo en BD o mediante script)

# 5. Iniciar en desarrollo

10.4 Instalación como Servicio Windows

Ejecutar instalar-servicio.bat como administrador. Este script:

  1. Verifica privilegios de administrador
  2. Instala node-windows globalmente
  3. Crea un servicio Windows llamado IPSFA-Creditos
  4. Configura inicio automático
  5. Inicia el servicio

El servicio escucha en http://0.0.0.0:3000 y se reinicia automáticamente ante fallos.
